> 先把問題看清楚，再決定下一步。
> 從具體現象出發，逐輪釐清影響、目標與限制，查證能查到的事實，並把還沒確認的想法記進假設清單。需要其他人的資訊或決策時，再彙整待確認事項。

本技能改編自 [WeAgileio/grill-boss_zh-TW](https://github.com/WeAgileio/grill-boss_zh-TW)，原始方法來自 [onlyLT/grill-boss](https://github.com/onlyLT/grill-boss)。此版本將情境調整為通用的問題探索，保留分輪提問、事實自查與假設清單。

## 你是否也遇過

- 只有一句模糊的想法，還說不清楚真正要解決什麼
- 看到了反覆出現的困難，卻不知道原因在哪裡
- 已經想到一個解法，但不確定它是否能解決問題
- 讓 AI 幫忙分析，卻拿到沒有依據的數字、背景與原因推測

「探索問題」會區分已知事實、推論與待驗證假設，讓下一步有依據。

## 它怎麼做事

### 1. 問題是一棵樹，先釐清起點 🌳

最初的想法可能混合了現象、原因猜測與預想解法。第一輪先釐清：發生了什麼、為什麼**現在**想探索、**誰**受到影響、希望什麼有所不同，以及已經知道或試過什麼。

### 2. 問題三分流 🚦

| 去向 | 例子 | 處理 |
|---|---|---|
| **自己查** | 現有資料、相關文件、可查證的事實 | 自行查證並記錄來源 |
| **問你** | 親身經驗、觀察、目的、偏好與優先順序 | 經驗題問實例，決策題附建議選項 |
| **待他人確認** | 受影響者的經驗、尚缺的資料、資源與限制 | 有需要時才收進待確認事項 |

提問按**前線分輪**：集中詢問現在就能釐清的問題；依賴未知資訊的問題，等前置資訊明確後再問。使用者已提供的資訊不重複問。

### 3. 待確認事項：找對資訊與決策來源 📋

只有需要其他人提供資訊或做決定時，才整理這份清單。每項註明向誰確認、為什麼需要，以及會影響哪個判斷。決策題提供選項與理由；經驗題請對方描述具體情境，避免誘導答案。

低風險、可調整的假設可以先支持後續探索；對問題定義或下一步影響大的未知事項，優先確認。

### 4. 假設清單：把猜測與事實分清楚 📒

暫時無法確認的原因或決策，記錄為「假設內容、目前依據、猜錯的影響、如何驗證」，隨探索結果一起交付。具體數字要有來源，或清楚標為估計與假設，方便後續補證據、調整判斷。

### 5. 時間有限，先釐清關鍵問題 ⏰

時間有限時，集中一輪釐清最關鍵的問題，其餘標為明確假設或待驗證事項，讓階段性結論保留必要的不確定性。

## Before / After

**沒有「探索問題」：**

> 「原因一定是流程太複雜。直接做一個新工具，就能提升效率 40%。」
>
> （原因與數字都缺乏證據，解法卻已經被當成結論。）

**有「探索問題」：**

> 「先描述最近一次發生的情況：誰遇到什麼困難，帶來什麼影響？目前有哪些資料支持你的原因猜測？釐清後，我們再決定優先驗證哪個假設。」

## 安裝

在 Codex 使用時，將本儲存庫的 `SKILL.md` 與 `agents/` 複製到使用專案的 `.agents/skills/explore-problems/`，完成後技能檔案的位置為：

```
.agents/skills/explore-problems/SKILL.md
```

`agents/openai.yaml` 提供「探索問題」的顯示名稱與簡介。若使用 Claude Code，可將技能放在專案的 `.claude/skills/explore-problems/`。

## 使用

對 agent 說人話即可自動觸發：

- 「幫我釐清問題，我有個想法但還不清楚」
- 「不知道問題出在哪，想先探索可能的原因」
- 「先幫我想清楚要解決什麼，再討論做法」

也可以直接叫它：「探索問題」；在 Codex 也可以使用 `$explore-problems`。

## 原版驗證與本地調整

原版 README 記載了針對編造數字與時間壓力的測試，例如：

- 編造未查證的日期或比例 → 要求查證來源或明確標示假設
- 時間緊迫時直接給出方案 → 壓縮提問輪次，保留關鍵釐清步驟

本地版本將適用情境改為問題探索，保留事實查證與假設記錄，並區分探索經驗的開放式問題和需要選擇的決策題。原版測試紀錄不代表此版本已完成行為驗證。

## 來源與致謝

來源為 [WeAgileio/grill-boss_zh-TW](https://github.com/WeAgileio/grill-boss_zh-TW) 與其原版 [onlyLT/grill-boss](https://github.com/onlyLT/grill-boss)。本地版本更名為「探索問題」，並調整觸發語句、角色與範例。

依原版說明，其設計源自 Matt Pocock 的 batch-grill-me，包含依問題依賴關係分輪提問、事實自查，以及將決策留給當事人。本地版本沿用這些做法，並將待確認事項與假設清單用於通用問題探索。

## 免責聲明

探索結果取決於當前資訊，可能隨新證據調整。尚未驗證的原因與假設應保留標記，並在下一步持續查證。
