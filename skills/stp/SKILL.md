# STP：同步產品脈絡

將目前對話中「value-proposition 的產出」、「product-goals 的產出」與「market-segments 的產出」整理為供後續 agent 使用的專案背景。使用者提到的 market-segements 指 market-segments。預設使用繁體中文，保留原有專有名詞。

## 同步規則

1. 以目前工作專案根目錄的 `RPO-CONTEXT.md` 為目的地；既有產品技能會讀取此檔。若使用者指定其他明確目的地，依其指定。同步前先讀取現有檔案。
2. 只取對話中三類技能的實際產出及使用者對這些產出的明確修訂、選擇或確認；不要求技能必須以特定指令呼叫，內容可辨識即可。不加入其他對話、完整 PRD、功能需求或自行創造的內容。
3. 按主題整合最新有效版本：明確修正取代舊內容，仍有效的資訊予以保留。候選方案保留其候選狀態；使用者尚未確認的內容不能寫成已確認決策。不要把工具執行成功或建立技能本身當作產品資訊。
4. 對話未提及某類或某欄位時標記「尚未提供」，不可臆測或憑空補齊。若只更新其中一類，保留既有檔案中其他兩類的有效內容；有衝突且無法判斷哪項有效時保留雙方並標示「待釐清」，不擅自選擇。
5. 每項內容區分「已確認」、「候選／建議」、「待驗證」或「待釐清」，並簡短註明來源是使用者決策或對話中的技能產出；保留相關數值、期限及其條件。狀態不明時標示「待確認」。不聲稱來源已驗證。
6. 檔案只包含以下三個主題及理解它們所必需的狀態與來源。若既有檔案含其他內容，不直接刪除：先告知使用者並詢問如何處理，避免丟失既有資料；本次可先準備三個主題的內容。若檔案不存在，直接建立。
7. 寫入後簡短回報檔案位置、已更新的主題，以及缺少或有衝突的資料。不因缺少資料而虛構內容，也不自動執行其他技能來產生新內容。

## Agent 可讀格式

使用以下 Markdown 結構，內容保持精簡、具體，可有多個客群或目標；只填入已有資訊，無資料的欄位可合併為「尚未提供」。

```markdown
# 產品脈絡

## 價值主張
- 狀態：已確認／候選／待確認
- 目標顧客：
- 顧客需求或問題：
- 產品及類別：
- 主要能力與價值：
- 替代方案及差異：
- 來源／待驗證事項：

## 產品目標
### 目標名稱
- 狀態：已確認／候選／待確認
- What：
- Why：
- KPI：定義、基準、目標值、衡量期間
- ROI：
- Done by：
- 來源／待驗證事項：

## 市場客群
### 客群名稱
- 狀態：已確認／候選／待確認
- 特徵及情境：
- 待完成任務（JTBD）與期望成果：
- 痛點與障礙：
- 產品適配及採用障礙：
- 現有替代方案：
- 優先順序：
- 來源／待驗證事項：
```

需要時增補同一主題內有意義的欄位，例如市場規模與證據；保留原始產出中對理解決策必要的資訊，但不為填滿模板增加沒有依據的內容。
